# 透明视频最小示例

本目录可直接导入，附带无角色版权依赖的 64×64 合成测试图：从左到右为透明、半透明和不透明区域，彩色区域随时间变化。它验证视频播放能力，不代表成品角色美术。

`runtime-probe.mp4` 是 128×64 的普通 H.264 / avc1 MP4，12fps、1 秒；左半为直通 RGB，右半为灰度 Alpha（黑=透明、白=不透明）。播放器提取后得到 64×64 透明图。上半 RGB、下半 Alpha 时将 `layout` 写为 `top-bottom`。

状态 `media` 必须显式包含 `type: "alpha_video"`、包内 `.mp4` 的 `path` 和 `layout`，不能填写 `fps`。允许与 PNG/WebP 按状态混用；`loop`、`next` 与其他媒体相同。首版统一静音，不提供视频内音频开关。

限制：本地自包含、单视频轨、非分片 MP4；不支持旋转轨道或外部媒体引用。文件不超过 128MiB，拼接后的宽高均为偶数且不超过 2048，拼接轴为 4 的倍数；时长最多 300 秒、最多 18000 帧、每帧间隔 1/60–1 秒。色彩转换与有损压缩可能影响透明边缘，素材制作时应避免过度压缩、RGB/Alpha 边界污染与预乘 Alpha 输入。

导入检查容器/路径/尺寸/时序，不完整播放五分钟视频；实际解码失败会提示并回退 idle。播放时异步送帧，隐藏默认暂停；低功耗保留视频原时序，未承诺降低解码开销。首次加载可能有延迟，解码器与 GPU 内存不等于应用当前显示帧缓存。

当前 Qt 6.5.3 在真实素材上出现硬解 surface pool 耗尽，因此产品默认软件解码以保证当前验证路径稳定，可能增加 CPU 开销。此默认仅在程序进程内设置，不改系统环境；开发者显式传入硬件解码环境变量时保留其覆盖，但硬解稳定性未验收。

完整包附带 Qt 视频后端及运行库，无需另装 FFmpeg 命令行、Python、Qt 或编译器。源码开发输出须用匹配 Kit 的 `windeployqt` 部署。`QtDesktopPet.exe --check-video-runtime` 在单实例/个人配置之前解码本样本，自检成功输出 `VIDEO_RUNTIME_PASS`；不会打开已有桌宠。

样本生成器仅在开发仓库 `internal/qa/scripts/make_alpha_video_fixtures.py`，编码器仅为开发测试依赖。作者向导和正式批量素材转换工具仍留 B6。
